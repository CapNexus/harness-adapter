How we measure

We run known token volumes through each vendor's own coding tool and read the plan's quota meter as it ticks. Pricing those tokens at list API rates gives the dollars one point of quota is worth. Every plan is valued on one standard agentic coding mix: 95.3% cached context re-read, 4.4% new input, 0.3% output. New input on Claude plans is priced as the 1-hour cache write Claude Code makes (2× input), and on Kiro as a 5-minute write (1.25×).

Scaling tiers

Anthropic and OpenAI now size tiers in proportion to price, so one measured tier sets the rest. Claude was metered on a Team Premium seat (6.25× Pro at $125/mo). Prices are monthly billing; a month is 52/12 weeks.

Caveats

ChatGPT was metered on the $200 Pro tier with nothing else running on the account: GPT-6.2 Sol and Astra one token type at a time, valued on our standard agentic coding mix. The $500 Pro tier and Plus are scaled by price. Kiro sells a credit budget; its Claude 5.5 models were metered per token type and valued on the same agentic mix. "All labs" ranks each plan on its highest-value model.

Why bytes

The same text is about 1.5× more tokens on Claude's tokenizer than on OpenAI's, measured on nine slices of real agent transcripts (range 1.40–1.59×). Bytes of agent text don't depend on the tokenizer, so they compare across labs. We use agent-transcript text, where Claude runs about 2.3 characters per token; prose packs about 1.5× more.

How we convert

Plan dollars buy quota; our meters give quota per token for each model and token type. Claude uses the measured 5-hour point rates. GPT-6.2 Sol and Astra use weekly point rates measured separately for new input, cached input and output on ChatGPT Pro. GPT-6.1 Sol on Devin uses its list-price value multiple ($2 input / $0.10 cached / $10 output).

Caveats

This is capacity, not work done: models differ in how much they write per task. Haiku depends on prompt size. Per-turn overhead also varies by harness.

In-plan value · by model, within one plan

Plan meters charge some models more than their list price implies

Quota meters do not charge models in proportion to their API list prices. One plan dollar therefore buys more API value on some models than on others. Each row shows a model's list price and quota cost as multiples of the plan's reference model, then the API value one plan dollar buys at 100% use.

One basis

Every figure on this tab uses our standard agentic coding mix: 95.3% cached context re-read, 4.4% new input, 0.3% output, by tokens. List price and quota cost are each the cost of one million tokens of that mix. New input is priced as the cache write each tool makes, because that is what the same tokens would cost on the API: the 1-hour cache on Claude plans (2× the input price), the 5-minute cache on Kiro (1.25×), ordinary input on ChatGPT.

Reading a row

List price and quota cost are multiples of the reference model in the same plan. If the quota multiple is smaller than the list multiple, the meter charges that model less than its list price implies, and a plan dollar buys more on it. The bar is API list dollars per plan dollar at 100% use.
